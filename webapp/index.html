📖 使用说明

Everything you need, 不用再翻别的页面
① 怎么让设备走代理（最常用）

在手机 / 电脑的网络设置里填代理地址即可，NAS 侧不用改任何东西。

设备在哪填怎么填
Windows设置 → 网络和 Internet → 代理192.168.3.3 端口 7890
安卓Wi-Fi 长按 → 修改网络 → 高级 → 代理主机 192.168.3.3 端口 7890
iPhoneWi-Fi → ⓘ → 配置代理 → 手动服务器 192.168.3.3 端口 7890
浏览器装 SwitchyOmega 扩展选 HTTP 代理，填 192.168.3.3:7890

SOCKS5 专用

需要 SOCKS 协议时（比如某些游戏客户端、Git）用端口 7891。

验证是否生效

填好后访问 ip138.com 或 ip.sb，如果显示日本/美国 IP 就成功了。 若还是国内 IP，看下面「排错」。

② 各个端口都是干什么的
端口用途谁来用
7890HTTP / SOCKS5 混合代理你的电脑 / 手机 / 电视盒子
7891纯 SOCKS5 代理只支持 SOCKS 的软件
8090本控制台（说明+控制+状态）浏览器
9090mihomo 原生面板（备用）需要看详细日志时

为什么有两个网页面板

9090 是 mihomo 自带的 metacubexd，只能看不能改订阅。 8090 是本页面，能更新订阅、能启停容器。日常用 8090 就够了， 右上角有「备用面板」链接。

③ NAS 上的软件要走代理吗？（重要）

默认不走。mihomo 是个「等待接入」的服务，不是全局接管。 任何软件都得自己配置代理才会走。

实测证据

  • NAS 宿主机没有任何 http_proxy 环境变量
  • NAS 直连 google.com 超时，走 7890 才通 → NAS 本身不在代理里

让某个软件走代理的3 种办法

  • 环境变量（适合命令行 / 容器）： export https_proxy=http://192.168.3.3:7890 Docker 里在 docker-compose.yaml 加 environment: 同名变量
  • 软件自带设置：qBittorrent 等下载器在设置里填代理地址
  • 给 git 单独配：git config --global http.proxy http://192.168.3.3:7890

哪些该接、哪些别接

软件建议原因
qBittorrent别接BT 流量走代理会跑满机场、易封号
Emby / 影音别接局域网播放不需要
nas-tool刮削建议接解决刮削失败、图片拉不到
MoviePilot建议接媒体信息源需要外网
Git 拉 GitHub建议接这就是做代理的初衷
⚠️ 容器里不能用 127.0.0.1，要用 192.168.3.3（容器内的 127.0.0.1 是容器自己）
④ 节点掉线了怎么办

免费机场的节点经常挂，这是常态。本setup 已经有自愈机制：

  • ♻️ 自动选择 组是 url-test 类型，每5 分钟自动测速， 掉了会自动切到最快的可用节点 —— 你什么都不用做
  • 想让主组也走自动：点 🔰 选择节点 → 选 ♻️ 自动选择

手动干预

  • ⚡ 全部测速：一次性测所有节点延迟，绿的可用
  • 🎯 自动选最快：跑脚本探测并把主组切到最快节点
  • ⚡ 刷新订阅：只重新拉一次订阅，几秒完成，不改配置
  • 🛡 自动守护：每 3 分钟用真实流量检测当前节点， 断了自动切到可用节点（推荐开着）
  • 或者直接点某个节点名字即可切换

为什么测速绿灯但还是打不开？

「全部测速」打的是 generate_204 这种空响应， 只能证明隧道建立成功 + 收到 1 个字节，不验证 TLS 握手和真实传输。 节点可能出现「延迟 150ms 绿灯，但 google / github 全打不开」。

🛡 自动守护用的是真实 HTTPS 请求（google + cloudflare）， 页面上会标出 ✅ 实测通 / ❌ 实测不通，这个才准。 免费机场节点经常时好时坏，建议常开。

接不上某个节点怎么办

本 setup 里节点域名走了强制直连解析（nameserver-policy）。 换机场后如果所有节点全超时，八成是漏了新机场的节点域名后缀 —— 不同机场后缀不同（实测见过 fr0528.art、qpon 等）。

查当前节点域名：订阅链接里 grep 'server:'， 或直接看 /volume1/docker/clash/config/config.yaml 的 dns.nameserver-policy，把所有后缀都补进去。 用通配符（+.域名后缀）而不是完整域名，机场轮换子域名时才不会失效。

为什么默认不自动选？

默认走 🔰 选择节点（手动），不是 ♻️ 自动选择。原因：

url-test 在全部节点都挂时会退化成选列表第一个节点， 而那个通常也是挂的 —— 实测会导致 github / google 直接报 error: xxx-node，整条链路失效，但界面看起来一切正常（很难排查）。

想要自动切换就在上面点 ♻️ 自动选择 组里的节点即可； 只要有一个节点活着，自动组就能正常工作。

⑤ 订阅和流量

平时需要做什么

什么都不用做。 mihomo 每小时（interval: 3600）自动拉一次订阅， ♻️ 自动选择 每5 分钟自动测速切节点。

什么时候要点「立即拉取」

  • 换了订阅链接 → 在输入框粘贴新链接 → 点「拉取」
  • 机场临时加了新节点 → 等不及一小时，点一下立即生效

流量看什么

左上角圆环是机场流量（机场侧统计），和节点实际消耗一致。 「实时速率」是 NAS 当前的总上传/下载速度。

流量用完了

换一家机场，然后在上方输入框填新订阅链接点「拉取」。

⑥ 排错
现象原因 & 解决
设备填了代理但没网 看顶栏容器是否 运行中； 停止状态下 7890 端口不存在。先点「▶ 启动」
全部节点超时 先点「⚡ 全部测速」。全红 = 机场侧问题或本地网络问题， 不是本页面故障；先重启容器试试
页面打不开 确认地址是 http://192.168.3.3:8090/， 不要用 127.0.0.1（那是你自己电脑）
点了没反应 看「实时日志」标签页，mihomo 会把错误原因推给你
点测速全是"超时"但代理其实能用 老版本现象。当前已改为用 Cloudflare 的 204 测速（gstatic 在 部分机场节点上会404）。若仍全超时，多半是机场侧拥堵，等几分钟再试
国内网站也变慢 模式被切到「全局」了 → 切回「规则」
广告没被拦 确认「🛑 拦截广告」组指向 REJECT，模式为「规则」

⑦ 这个页面是怎么工作的（架构）

数据来源

  • mihomo RESTful API（9090）：节点、连接、规则、日志
  • 本页面后端（8090，Python 标准库）：订阅信息 +转发所有控制指令

为什么需要后端转发

浏览器有跨域限制，且订阅流量信息在机场的响应头里、启停容器要调 docker 命令， 都不能纯前端完成。

服务管理

本页面由 systemd 托管：sudo systemctl restart sub-panel 重启服务，sudo systemctl status sub-panel 看状态。已设开机自启。

能做什么、不能做什么

✅ 切节点、切模式、启停容器、更新订阅、看连接与日志
❌ 不能在网页上新增/编辑节点 —— mihomo 的 API 是只读的，没有写节点的接口。 要加节点得手动改 config/providers/local.yaml。
